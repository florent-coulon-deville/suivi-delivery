# Contexte pour Claude Code

## Projet

Application **« Suivi de la delivery »** (nom technique : `suivi-delivery`) : suivi des mises en production (MEP), qui remplace un suivi prévu sous Excel.

- **Noms** : titre affiché « Suivi de la delivery » ; noms techniques `suivi-delivery-*` (paquets, images publiées ; sur le poste, docker-deploy suffixe tout en **`-local`** : conteneurs et images `suivi-delivery-{backend,frontend}-local`, réseau `suivi-delivery-local`, volume des données `suivi-delivery-data-local`, choix de l'utilisateur). « MEP » reste le terme métier dans les textes. Anciens noms : release-management, suivi-mep.

- **Cible de déploiement** : OpenShift.
- **Version légère** (branche `feat/version-light`, demande de l'utilisateur : « juste un front et un back », pas de gestion de compte dans un premier temps) : **deux programmes seulement**, l'API et l'interface. **Plus de PostgreSQL, Liquibase ni Keycloak** (modules `postgres/`, `liquibase/`, `keycloak/` retirés), **plus de connexion, de comptes ni de rôles** : tout le monde peut tout lire et tout saisir (interface à réserver à un réseau de confiance ; l'API n'est jamais exposée). La version complète (PostgreSQL + Liquibase + Keycloak) reste sur `main`.
- **Stockage : SQLite**, un seul fichier (`APP_DB_FILE`), une vraie table par objet (`app/storage_sqlite.py`), mêmes opérations que le stockage en mémoire (`app/storage.py`, `MemoryStorage`, utilisé sans `APP_DB_FILE` : tests, essais). Pas d'ORM (module `sqlite3` de Python). Une transaction par requête (`app/transactions.py`, commit juste avant la réponse), **une requête à la fois** (une connexion, un `threading.Lock`), essai de cohérence dans un savepoint ; **un seul exemplaire de l'API** sur un fichier (chart : `backend.replicas` 0 ou 1, `Recreate`). `IntegrityError` de la base → 409 (filet de sécurité). **Structure appliquée par l'API elle-même au démarrage** : fichiers numérotés `backend/app/sql/NNN-*.sql` (`001-tables.sql` : 14 tables, contraintes nommées `pk_`, `uq_`, `ck_`, `fk_` en ligne, index `ix_`), numéro du dernier appliqué dans `PRAGMA user_version`, base plus récente que l'API refusée ; **ne jamais modifier un fichier appliqué**, toujours en ajouter un. Booléens 0/1, dates en texte ISO UTC, JSON en texte (convertis par `storage_sqlite.py`). Journal des actions **sans auteur**. Guide : [docs/sqlite.md](docs/sqlite.md).

## Préférences de l'utilisateur (à respecter)

- Répondre **en français**, de façon concise et directe. Une seule question à la fois si une précision est nécessaire.
- **Toujours demander validation avant d'agir** : écrire ou modifier du code, faire un choix technique, lancer une commande qui a un effet (git, docker…). Proposer, expliquer, attendre le « ok », puis agir.
- **Parler métier, pas technique**, et rester sur la forme générale : ne pas entrer dans les détails tant que l'utilisateur ne le demande pas.
- **Avancer par petites étapes simples**, que l'utilisateur comprend. Pas d'architecture complexe : il a explicitement refusé l'ancienne architecture en couches (domaine / data / api, Alembic).
- L'utilisateur découvre ces outils : **expliquer** les outils et les choix pour qu'il puisse trancher.
- Fournir du code complet et fonctionnel, **bien documenté** (code et `docs/`).

## Consignes techniques

- **Code en anglais, commentaires en français** (décision de l'utilisateur, branche `refactor/code-en-anglais`) : noms de variables, fonctions, classes, fichiers et dossiers, adresses de l'API et champs JSON, tables et colonnes, valeurs des listes fermées, clés Helm, options et variables des scripts et de la CI, classes CSS. Restent en français : commentaires, docstrings, documentation, textes affichés (écrans, messages d'erreur, onglets et colonnes du fichier Excel), titres des requêtes Bruno, données d'exemple. Lexique : [docs/glossaire.md](docs/glossaire.md).
- Tout le code de l'API est dans `backend/`. Python 3.14, géré par uv.
- L'interface web est dans `frontend/` : **Next.js 16 + React 19 + TypeScript** (strict), CSS maison (`app/styles.css`), sans bibliothèque de composants. Node 26 (MacPorts sur le poste de l'utilisateur ; dans un shell non interactif, ajouter `/opt/local/bin` au PATH). **Le navigateur ne parle jamais à l'API** : le serveur Next.js la lit (`lib/api.ts`, `API_URL`), calcule l'état (`lib/state.ts`) et écrit via des Server Actions (`app/edit/actions.ts`, entrées vérifiées). Garder le maximum en composants serveur ; `"use client"` seulement pour l'interactif. Jamais l'adresse de l'API dans une page. Qualité : `npm run typecheck` et `npm run build` doivent passer.
- **API** : respect strict des méthodes REST et des codes retour HTTP. Méthodes : GET, HEAD, OPTIONS (204 + `Allow`), POST (201 + `Location`), PUT (remplacement complet, 200, 404 si absent), PATCH, DELETE (204). Codes : 400 (illisible), 404, 405 (+ `Allow`), 409, 415 (pas du JSON), 422 (contenu invalide). Règles communes dans `app/http.py`. Voir [docs/api.md](docs/api.md).
- **Toujours mettre à jour la doc** (`README.md`, `docs/`, ce fichier) avec le code.
- Une ressource = un fichier dans `backend/app/routes/` + un fichier de tests.
- **Règle d'or de l'utilisateur : on ne peut pas saisir quelque chose d'incohérent**, et ça vaut pour tout. Toute saisie qui rendrait les données fausses est refusée (409 ou 422), avec un message clair. Les règles d'ensemble sont dans `app/consistency.py` (essai sur une copie avant d'appliquer) : cluster du même type que l'environnement, pas de snapshot en prod, modules requis présents (même sans condition de version) et compatibles.
- **Projet neutre** (demande de l'utilisateur) : aucune référence à une entreprise (nom, service informatique, codes internes) dans le code, les tests, la doc ou les exemples : environnements d'exemple `int`, `rec`, `preprod`, `prod` ; zones réseau `dmz`, `interne`, `partenaires`, `admin`, `devops` ; code d'application de 3 caractères = **trigramme**.
- **Namespaces** : uniques par application + environnement + **cluster** + suffixe (le même nom une fois par cluster, contrainte `uq_namespaces_application_environment_cluster_suffix`) ; l'interface affiche le cluster à côté du nom.
- Unicité toujours vérifiée **au sein de l'application** (sauf l'identifiant d'application, unique partout).
- **Tout en minuscules** : codes, identifiants, trigrammes, suffixes sont convertis en minuscules.
- **Réglages par variables d'environnement**, lus au lancement, jamais en dur dans le code (une même image Docker pour toutes les instances). Backend : `app/settings.py` (`APP_HOST`, `APP_PORT`, `APP_LOG_LEVEL`, `APP_DOCS`, `APP_DB_FILE` (fichier SQLite ; défaut de l'image : `/data/suivi-delivery.sqlite`) ; tests sur une base : `TESTS_DB_FILE`, nom finissant par `_tests.sqlite`). Noms des variables en anglais, le reste en français. Frontend : `API_URL`, `PORT`, `INSTANCE_NAME`, `INSTANCE_COLOR` (`frontend/lib/settings.ts`, lus au lancement du serveur Next.js ; `PORT` sur la ligne de commande en dev). Voir [docs/deploiement.md](docs/deploiement.md).
